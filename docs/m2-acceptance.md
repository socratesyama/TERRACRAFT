## 実装範囲
気温（§7.2）、水分・日照（§7.4）、バイオーム（§7.5）、植生（§7.6）、tick への結線（§10.1 の 2・3・5・6 段）。
描画レイヤー: 地形 / 降水 / 気温 / 水分 / バイオーム / 植生。統計パネルにバイオーム割合と陸の平均植生。
開発者向けパネルに降水倍率スライダ（`param` Op → `rainfallScale`。「乾燥」は通常ツールにしない §21）。

## 自動確認（`tests/m2.test.ts`）

- 3プリセットで同じ seed・同じ tick 数 → World と派生配列のハッシュが一致。
- 降水を 0.2 倍で植生が減り、2 倍で増える（乾燥化テスト）。気温補正が効く。
- 盆地で風下斜面の砂漠割合 > 風上斜面。

## 観察された問題（コードは計画書どおり。データ・仕様側の事情）
1. **陸の大半が「砂漠」になる。** 陸の降水の中央値が island 125 / mountainRange 131 mm/年で、`climate.precip.qFloor`
   （0.08）の下限（0.08×0.06×25000 = 120 mm）に張り付く。Whittaker の砂漠は 250 mm 未満。
   `qFloorDoc` は「200〜400 mm 相当」と書くが、現在の定数では 120 mm で、データ内の説明と値が合わない。
2. **風上斜面が低地より乾く。** mountainRange（風は西）では風上斜面 176 mm、風下斜面 135 mm、平地 287 mm。
   山脈の風上側に海が接している範囲が狭く、湿った空気が海岸で尽きる。
   プリセット幾何（`terrain.json`）と風向（`scenarios.json`）の組み合わせの問題。盆地では風上 1883 / 風下 1229 mm で効く。
3. **植生の収容力 Kcap（§7.6）に砂漠でも約 0.4 の下駄がある。** 日照 0.3×0.4〜1 と温度適合 0.2 が水分と無関係に効くため、
   降水を 1/5 にしても平均植生は約 9% しか減らない（方向は正しい）。
4. 季節変化（§7.2 の `sin(season)`）は未実装。M3 以降。

## 目視手順（ブラウザ）
`npm run dev` → 「バイオーム」レイヤーで色分けを確認。「降水」「気温」「水分」「植生」を切り替える。
再生すると植生が数十 tick で広がる。開発者向けパネルの降水倍率を下げると砂漠が広がる。

## 承認を受けた仕様調整（2026-11-17、「ゲームとして面白くなるなら変えてよい」）
- 降水: `baseRainFrac` 0.06→0.015、`calibration` 25000→100000、`qFloor` 0.08→0.12。海上の降水（約1500 mm）は同じで、陸の奥まで湿気が届き、風上斜面は 1000〜3500 mm、風下の雨陰は 180〜400 mm 程度になった。
- 収容力: `capacity.moistureGate` を追加。乾燥化で植生が実際に減る（島: 対照 0.483 / 降水×0.2 で 0.240 / ×2 で 0.619）。
- 結果（192²、陸に占める砂漠の割合）: island 42%、mountainRange 37%、basin 6%。風上 994 / 風下 182 mm（island）。熱帯雨林・温帯林・草原・サバンナ・砂漠が共存する。
- 上の「観察された問題」1〜3 は、この調整で解消した。数値は調整前のものとして残している。
