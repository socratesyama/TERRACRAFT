# M3 受け入れ手順（文明・干渉・Undo）

## 実装範囲
- 集落（§8.2〜8.3）: 居住適性（水・平地・植生・交通 − 洪水リスク）、4 tick ごとの発生、ロジスティック成長、農地、階層（村/町/都市/港町）、移動（洪水リスク・過密）。
- 洪水リスクの事前計算（§8.1: hand / drainAcc / floodRisk）。
- 道路（§8.4）: A* で 1 tick に 1 本、標高が変わったら引き直し。
- 災害（§8.5）: 洪水（豪雨・rain Op）、干ばつ（ヒステリシス）、土砂災害。原因つきでログに残る。
- 干渉 Op（§9.2）: 盛り土・山削り、植林・伐採、ダム（両端を谷壁へスナップ、ドライランで新しい湖を予告）、埋め立て、param、豪雨。
- Undo/Redo（§9.3）: Op 直前のスナップショットのリング（runtime.history.snapshotRing = 8）。
- イベントログ（§9.4）: 検出器（川・湖・森林率・砂漠率）、Op への causeId の紐づけ、同種の間引き、クリックでカメラ移動。
- UI: ツールパレット、ブラシ、元に戻す/やり直す（Ctrl+Z / Ctrl+Shift+Z）、できごとログ、集落パネル、洪水リスクレイヤー。

## 自動確認（`tests/m3.test.ts`）
同じ seed で集落・道路を含めハッシュ一致 / 発生地点が水に近く水域に無い / 人口が発散しない / 最小間隔 /
Op で標高が変わりログに因果が付く / Undo で完全に元に戻り Redo + 再実行で一致 / 別コントローラで同じ操作列を再生して一致 /
植林・伐採 / ダム（壁は元の標高以上、ドライランは世界を変えない）/ 失敗した Op は巻き戻る。

## サンドボックスでの数値確認（vitest は未実行、Node で同じ条件を直接確認）
- 500 tick（128²）: island 57 集落、mountainRange 60、basin 60。集落の水までの平均距離 2.7 / 3.7 / 3.2 セル（陸の平均 10.5 / 9.4 / 2.1）。最大人口 2,300〜2,600。水域上の集落 0。
- 192² の 1 tick は平均 7〜10 ms、最悪 50 ms 前後（道路の A* と居住適性の再計算の tick）。
- Undo → 元のハッシュに完全一致、Redo + 30 tick → 元と一致、別コントローラ → 一致。

## 計画書との差分（理由つき）
1. **Kc の式。** 計画書の「農地半径 = sqrt(人口×0.004/π)」では農地 1 セルが 30 人を支えるため、人口が 500 に届かない（自己矛盾）。
   Kc = 集水域（半径 6 セル）の農地バイオームの肥沃度の合計 × 30 とし、農地は人口に応じて集落に近い順に開墾する。`settlements.json` に追加。
2. **道路は「最近傍グラフ + MST」を「新しい集落と最も近い既存集落を結ぶ」で近似**（木になる）。Dijkstra の予算 4,000 ノードは、途中再開をせず、A* で 1 tick 1 本とした。
3. **スナップショットのリングは Op 直前のものだけ**（50 tick ごとの定期スナップショットは M5 の時間スライダで入れる）。Undo はその時点へ時間ごと戻る。
4. **災害は計画書 §8.5 の 3 種（洪水・干ばつ・土砂）。** `disasters.json` にある山火事・地震・嵐は未実装。自然の豪雨は `storm.probPerTick` 相当の確率で洪水を起こす。
5. **「変化前後の差分ヒートマップ」は未実装**（§9.4 の UI。M5 の因果トレーサで）。
6. 国家モード（§21）への切替は M4。干渉ツールは神モード（§9）のまま。
