# M10 受け入れ記録（侵食エンジン・侵食レイヤー）

## 重大な発見（これまで報告していなかった抜け）
計画書 §6（河川侵食・土砂の輸送と堆積・斜面崩壊）は、「削らないもの」に入っているのに **M1〜M9 では実装されていなかった**（データ `hydrology.json` に係数だけがあり、エンジンが無かった。UI の侵食レイヤーも「後のマイルストーンで使えます」のままだった）。この M10 で入れた。M1〜M3 の受け入れ記録で水文・侵食を「済み」と読める箇所があれば、それは誤り。

## 実装
- `src/core/terrain/erosion.ts`: 河川侵食（n=1 の陰的解法、Braun & Willett 2013）、土砂の輸送と堆積（運搬能力 `Kc·A^m·S` を超えた分を堆積 → 河口に三角州）、斜面崩壊（安息角を超えた分の半分を低い側へ。差分配列で一括適用）。係数はすべて `hydrology.json`（streamPower / sediment / slopeStability）。
- 実行頻度: 4 tick に 1 回（高速モードは 8 tick）、`dt` は間隔ぶんをまとめて渡す（`runtime.json schedule`）。標高が変わるので流向・勾配を引き直すが、**道路は引き直さない**（`recomputeTerrainDerived` のみ）。
- 倍率 `erosionRate`（`hydrology.json streamPower.rate`、0〜20、既定 3）。Op の param で変えられ、URL 共有にも入る（param の番号は末尾に追加したので、既存の共有 URL は読める）。
- 植生が侵食を最大 80% 減らす → 伐採で侵食が増え、植林で抑えられる（追加のルール無し）。
- 世界の状態に `primary.erosion`（標高の正味の変化）を追加し、hash・Undo・スナップショットに入れた。描画パックは 5 枚目のテクスチャ（R 侵食・堆積、G 輸送中の土砂）に増えた。
- UI: 侵食レイヤー（削れ = 暖色・積もり = 寒色、凡例付き）、開発者パネルに「侵食の速さ」スライダ。

## 設計判断
- 侵食の基準面は海面（受け手の標高を `max(受け手, 海面)` として解く）。これが無いと、陸が海面より下まで削れて領土に水域ができ、M4 のテスト（領土は水域を含まない）が落ちた。
- 堆積は標高 1 を超えない（残りは下流へ運ぶので保存則は保たれる）。
- 既定の倍率 3: island で 200 tick あたり最大 20〜30 m 削れる（実測。倍率 1 だと約 11 m）。

## テスト（`tests/m10.test.ts`、10 本）
保存則（Σ標高の変化 = −海へ出た量、削り = 堆積 + 流出）、倍率 0 で不変、植生が守る、倍率に比例、極端な dt でも発散しない、拘束セルは動かない、河口に堆積、斜面崩壊で総量が保たれる、決定論、時間経過で削れと堆積が残る。m1〜m9 も通った。

## 計測と注意
- 128² で、侵食ステップは約 11 ms（流向の再計算を含む）。192² では約 25 ms と見込まれ、4 tick に 1 回なので平均 6 ms/tick。33 ms の予算内だが、その tick は他の処理と重なるので、**実機での計測は未実施**。
- 侵食のたびに降水は再計算しない（変化が小さいため）。標高が大きく変わる Op のあとは従来どおり再計算される。
